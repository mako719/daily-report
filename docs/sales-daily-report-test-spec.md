# 営業日報システム テスト仕様書（叩き台）

※ 要件定義・ER図は `sales-daily-report-requirements.md`、画面は `sales-daily-report-screens.md`、API は `sales-daily-report-api.md` を参照。
※ 仮決め（【想定】）は Issue #1 ですべて確定した。新しい仮決めには【想定】を付け、合意したら外す。

## 1. テスト方針

| 種類 | 対象 | 確認すること |
|---|---|---|
| API テスト | 全API（`sales-daily-report-api.md`） | 正常系・入力チェック・権限・業務ルール |
| 画面テスト | 全画面（`sales-daily-report-screens.md`） | 表示の切り替え、入力操作、画面遷移、エラーメッセージ |
| 非機能テスト | 認証・セキュリティ | パスワードの保存方法、不正な入力への耐性 |

- 単体テスト（クラス・メソッド単位）は開発者が実装時に書くため、本書の対象外とする。
- 各テストは、下の「テストデータ」を投入した状態から始める。
- 文字数の境界値は、上限ちょうど（OK）と上限＋1（NG）の両方を確認する。

## 5. 非機能テスト

| ID | 観点 | 操作 | 期待結果 |
|---|---|---|---|
| NF-01 | パスワードの保存 | 営業を登録して DB の `password_hash` を確認 | 平文ではなく、ハッシュ化された値が入っている |
| NF-02 | 画面へのスクリプト埋め込み（XSS） | 訪問内容・コメントに `<script>alert(1)</script>` を入力して表示 | スクリプトは実行されず、文字列のまま表示される |

| NF-04 | セッションの無効化 | ログアウト後、ブラウザの「戻る」で前の画面を操作 | API が 401 になり、SCR-01 に遷移する |
| NF-05 | 改行の保持 | Problem に改行を含めて保存して表示 | 改行がそのまま表示される |
